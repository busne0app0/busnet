# Інструкція з виконання міграції BUSNET CONNECT FOUNDATION

Цей пакет підготовлено для безпечного ручного виконання міграції бази даних у Supabase SQL Editor.

---

## 📁 Склад пакету

| Файл | Призначення |
| :--- | :--- |
| `01_pre_migration_checks.sql` | Діагностика стану бази даних, перевірка кількості записів і поточної схеми (без змін) |
| `02_connect_foundation.sql` | Основна ідемпотентна транзакція розширення схеми, індексів, тригерів та RLS |
| `03_post_migration_checks.sql` | Контрольна перевірка структури, індексів, тригерів та кількості записів після виконання |
| `04_rollback_notes.md` | Інструкція та SQL для безпечного відкату змін у разі потреби |

---

## 🚀 Порядок виконання

### Крок 1. Перевірка перед міграцією
1. Відкрийте ваш проєкт у [Supabase Dashboard](https://supabase.com/dashboard).
2. Перейдіть до розділу **SQL Editor**.
3. Скопіюйте весь вміст файлу `01_pre_migration_checks.sql` та вставте його у редактор.
4. Натисніть **Run**.
5. **Очікуваний результат:**
   - Таблиця `forum_posts` містить існуючі записи (зафіксуйте їх кількість `total_records`).
   - Таблиця `forum_comments` містить існуючі коментарі.
   - Запит поверне список поточних колонок та категорій.

---

### Крок 2. Застосування міграції
1. Відкрийте новий запит у **SQL Editor**.
2. Скопіюйте весь вміст файлу `02_connect_foundation.sql`.
3. Натисніть **Run**.
4. **Очікуваний результат:**
   - Повідомлення `Success. No rows returned` (або `Query executed successfully`).
   - Усі дії виконуються всередині безпечної транзакції `BEGIN ... COMMIT`. У разі будь-якої помилки зміни не збережуться.

---

### Крок 3. Контрольна перевірка результату
1. Відкрийте новий запит у **SQL Editor**.
2. Скопіюйте весь вміст файлу `03_post_migration_checks.sql`.
3. Натисніть **Run**.
4. **Критерії успіху:**
   - Кількість записів у `forum_posts` і `forum_comments` **в точності дорівнює** кількості до міграції.
   - Стовпець `post_type` заповнено для всіх публікацій.
   - Стовпець `is_indexable` для всіх старих публікацій встановлено у `false`.
   - Тригер `trg_forum_posts_rate_limit` присутній та активний.
   - Таблиця `community_reports` створена з RLS.
   - Нові індекси присутні у списку `pg_indexes`.

---

### ⚠️ Що робити, якщо сталася помилка?
- Якщо Крок 2 видав помилку, транзакція автоматично відкотиться.
- Скопіюйте текст помилки та надішліть його для аналізу.
- За потреби зверніться до інструкції `04_rollback_notes.md`.
